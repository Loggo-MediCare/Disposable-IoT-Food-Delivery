## 2. 對照分析：Whoop 零件 → 本專案

| Whoop 零件 | 功能 | 本專案對應 | 成本意義 |
|---|---|---|---|
| 5IN1 飛控（FC＋4 路 ESC＋接收器＋VTX 整合） | 控制＋驅動＋通訊整合在一片板 | ESP32（BLE＋Wi‑Fi）＋雙通道 H-bridge 整合板 | **證實「整合成一片板」方向**：減少模組數、接頭與手工接線 |
| 4 顆無刷馬達 | 推力 | 2 顆 DC 減速馬達或 2 顆連續旋轉伺服 | 無刷需 ESC，單價高；本專案平地低速，**不需無刷** |
| 螺旋槳 | 產生升力 | 2 塑膠輪＋1 萬向輪 | 地面載具不需抵抗重力，所需功率遠低於飛行 |
| 1S LiPo 300mAh 75C | 高放電電源 | 3×／4× AAA 鹼性電池 | LiPo 需充電管理與運輸安全；一次性產品優先 AAA，但需驗證峰值電流 |
| JST-PH 2.0 電池接頭 | 快速更換電池 | AAA 電池盒＋彈片 | 兩者都是易漏計項目 |
| FPV 相機＋5.8GHz 類比圖傳 | 即時影像回傳給人 | 不裝（初版用場域共用相機＋AprilTag） | 相機＋圖傳是單台成本大宗；初版移出終端 |
| 機體 | 結構 | 便當盒本身＋薄型底盤＋雙面膠 | 容器本身就是機體，可省掉獨立機架 |
| PEEK 螺絲 ×15 | 輕量固定 | 雙面膠／卡扣 | 螺絲需人工鎖附；雙面膠更符合「貼上即用」 |
| 拆除馬達接頭、直焊 | 減重 | 工廠預製線束或整合板 | 手工焊接工時在量產中通常比料件更貴 |

### 2.1 從參考案例得到的結論

1. **US$230 是業餘玩家單件零售價**，遠高於「用完即丟」的目標，不能直接當本專案成本，只能用來檢查漏項。
2. **貴的是飛行，不是移動**：無刷馬達、ESC、高放電 LiPo、FPV 相機與圖傳都是為了飛行與人手操控。本專案改成平地、低速、自主，可以整類拿掉。
3. **整合板是降低成本的關鍵**：5IN1 飛控把四種功能做在同一片板上；本專案的對應作法是讓 ESP32＋H-bridge＋電源管理在同一片小板上（呼應設計紀錄第 3.2 節、第 11 節 #9）。
4. **人工成本不能忽略**：參考案例需 2–4 小時中高階焊接。本專案要求部署端「不焊接、不接 USB」，組裝端也應以預製線束與整合板為目標。
5. **小零件會被漏算**：接頭、線材、螺絲、天線都列在參考 BOM 中；本專案的電池盒、彈片、雙面膠、防拆封條也必須逐項列出。

### 2.2 飛行 vs. 滾動：為什麼不採用飛行方式

參考案例只是比較用的對照，本專案**從未採用飛行方案**。理由如下：

- 參考無人機整機不到 15 g，馬達推力只夠抬起自身並保留操控餘裕；範例便當裝餐後約 500 g，超過無人機自重 30 倍。
- 要吊起 500 g 需要大得多的機體與螺旋槳，高速槳葉靠近人與開放食品，與食品安全硬約束及低危害設計方向衝突。

力學比較（沿用設計紀錄第 2.3 節的示意假設：總重 500 g、`C_rr = 0.02`，**非量測值**）：

| | 所需的力 |
|---|---|
| 飛行（懸停，撐住全部重量） | `m g = 0.5 × 9.81 ≈ 4.9 N`，持續不斷 |
| 滾動（平地等速） | `C_rr m g = 0.02 × 0.5 × 9.81 ≈ 0.1 N` |

在此假設下，飛行所需的力約為滾動的 50 倍，而且懸停時一直耗電。

**對電池選擇的意義**：

- 飛行載具每一克都要計較，所以參考案例使用 300 mAh、75C 高放電 LiPo，並拆接頭、剝線皮減重。
- 滾動載具多幾克電池，所需推力幾乎不變；因此**便宜、較重的 AAA 鹼性電池是合理選擇**，同時省去 LiPo 的充電電路與運輸安全限制，符合用完即丟目標。
- 值得借鏡的是設計風格（整合式控制板、極少接線），不是飛行本身。

### 2.3 車載相機：參考 Ultra Tiny FPV 相機

參考案例使用 **Team Black Sheep Ultra Tiny FPV** 相機，整機含相機只有 13.5–14 g，證明「每台都裝相機」在**重量**上不是問題（對應設計紀錄第 7.2 節方案 B）。但這類 FPV 相機的影像路徑與本專案需求不同：

```
Whoop：  FPV 相機 ──類比影像──► 飛控板上的 5.8GHz VTX ──► 天線 ──► 操作者的 FPV 眼鏡（人看）
本專案：  相機 ──► ESP32 ──Wi‑Fi──► 中央主機（AI 判讀定位／避障）
```

| 比較 | 類比 FPV 相機＋5.8GHz VTX | ESP32 相機方案（具相機介面的 ESP32 型號＋小型相機模組） |
|---|---|---|
| 影像格式 | 類比，ESP32 無法直接讀取 | 數位，由 ESP32 擷取 |
| 傳到中央 | 中央需 5.8GHz 接收器＋影像擷取設備，每個同時運行的載具各佔一個頻道 | 走既有場域 Wi‑Fi，不需額外接收設備 |
| 同時運行台數 | 受頻道數限制（常用不互相干擾的頻道約 8 個） | 受 Wi‑Fi 頻寬與中央運算限制 |
| 延遲 | 極低（為人手即時操控設計） | 較高，但自主低速配送可接受 |
| 額外硬體 | VTX＋天線 | 無（共用 ESP32 與 Wi‑Fi） |
| 法規 | 5.8GHz 類比圖傳發射功率與執照規定**須查 NCC 規範** | 一般 Wi‑Fi 產品認證 |
| 適合本專案 | 低 | 較高 |

#### 混合方案：ESP32 控制＋AIO 類比鏡頭影像直出

ESP32 保留負責接收指令、雙馬達控制、BLE 配網、導航與容錯；另外並聯一顆極輕量的 **AIO 類比鏡頭圖傳模組**（相機＋VTX 一體），影像以 5.8 GHz 直接送到中央接收器，不經過 ESP32。

```
便當端：ESP32 ──Wi‑Fi──► 中央（指令、狀態、配網、容錯）
          │ MOSFET 開關（只在移動時供電）
          ▼
        AIO 類比鏡頭 ──5.8 GHz──► 中央 5.8 GHz 接收器 ─► 影像擷取 ─► NVIDIA 判讀
```

| 設計重點 | 說明 |
|---|---|
| ESP32 控制鏡頭電源 | 只在移動時發射：省電、同時佔用頻道的車數減少、降低隱私暴露 |
| 中央指派頻道 | 若 AIO 模組支援 SmartAudio／Tramp，ESP32 可經 UART 切換頻道；**需確認具體型號** |
| 共用 AAA 電源 | 不另加獨立電池（避免增加料件與廢電池）；須加濾波電容抑制馬達雜訊，並確認模組輸入電壓範圍 |
| 重量 | AIO 模組常見約 2–3 g，**須以實際型號確認** |

仍未解決：類比影像**未加密**（場域內任何 5.8 GHz 接收設備都能看到畫面，醫院場域隱私風險高）、NCC 法規、5.8 GHz 室內穿牆與轉角斷訊、AAA 能否撐住圖傳電流（需量測）。

**結論**：

- 若初版採**場域共用相機＋AprilTag**（設計紀錄第 7.2 節方案 A），終端不需相機，此項成本為 0。
- 若改採**車載相機**，應選可直接接 ESP32 的數位相機模組，而不是類比 FPV 相機＋VTX；參考案例的價值在於證明小型相機的重量可以忽略，不在於沿用其影像傳輸方式。
- 車載相機會增加料件、耗電（Wi‑Fi 傳影像）與中央運算負載，須以「單次安全成功配送成本」與共用相機的攤提比較後再決定。

## 4. 非料件成本

| 項目 | 計算方式 | 數值 |
|---|---|---|
| 組裝工時 | 每台分鐘數 × 每分鐘工資 | 待量測 |
| 部署工時 | 貼附＋BLE 配網＋註冊的秒數 × 工資 | 待量測 |
| 配網失敗重試 | 失敗率 × 重試工時 | 待量測 |
| 中央運算攤提 | 主機成本 ÷ 使用年限內配送次數 | 待估 |
| 場域相機攤提 | 相機成本 ÷ 使用年限內配送次數 | 待估 |
| 失敗食物損耗 | 失敗率 × 一份餐點成本 | 待量測 |
| 回收／廢電池處置 | 每台處置費 | 待查 |

## 5. 成本公式

沿用設計紀錄第 10.2 節：

```
BOM          = Σ（料件單價 × 數量）
部署成本/台   = 組裝工時 + 部署工時 + 配網失敗重試
營運成本/配送 = 中央運算攤提 + 場域相機攤提 + Wi‑Fi/雲端費用
單次安全成功配送成本 = (BOM + 部署 + 營運 + 失敗損耗 + 回收處置) ÷ 安全成功配送比例
```
