# 方案 R：遙控車式 FPV 架構（第 0 階段快速原型驗證）

> **狀態**：研究選項／原型驗證用，非量產架構
> **相關文件**：[PROJECT_DESIGN_RECORD.md](PROJECT_DESIGN_RECORD.md) 第 12 節、[BOM_AND_COST_MODEL.md](BOM_AND_COST_MODEL.md) 第 2.3 節

針對地面滾動智慧便當載具，為了解決初期韌體開發與即時影像控制的複雜度，本方案借鏡 FPV 無人機成熟的遙控與圖傳生態，作為快速驗證「中央主機遠端視覺操控」可行性的第 0 階段原型。

## 1. 系統架構設計

本方案將便當載具視為一台傳統遙控車，由中央運算主機（如 NVIDIA 主機）直接擔任「駕駛員」：

```
影像（下行）：便當端微型相機 ─► 5.8 GHz 類比圖傳(VTX) ─► 中央 5.8 GHz 接收器 ─► 影像擷取 ─► NVIDIA 判讀
控制（上行）：中央發射模組 ─► 2.4 GHz 遙控訊號（例如 ELRS） ─► 便當端遙控接收機 ─► 馬達驅動／轉向
```

註：常見 ELRS 接收機內部本身含 ESP 系列晶片，因此本方案並非「不用 MCU」，而是使用已寫好韌體的現成接收機。

## 2. 核心優勢

- **極低延遲**：類比圖傳為人手即時操控設計，影像延遲遠低於一般 Wi‑Fi 影像串流。
- **終端免影像處理**：相機訊號直接由 VTX 發出，車載晶片不需影像編碼。
- **現成模組化**：採用量產的遙控模型零件，第 0 階段不需自行開發終端韌體。
- **免除場域 Wi‑Fi**：以遙控系統的對頻（Bind）取代逐台配網。

## 3. 實際面臨的挑戰與限制

| 挑戰項目 | 說明與影響 |
| --- | --- |
| **同場運行規模受限** | 類比 5.8 GHz 在同一區域約只有 8 個互不干擾的頻道，車隊規模受限。 |
| **一對一遙控** | 遙控系統設計為一個發射器控制一台車；多台車需多個發射模組，或另行設計輪流控制。 |
| **隱私與安全** | 類比影像未加密，任何 5.8 GHz 接收器皆可看到畫面；照護場域隱私疑慮高。 |
| **室內穿透與訊號死角** | 5.8 GHz 穿透力差，轉角或電梯易斷訊。 |
| **法規與功率** | 5.8 GHz 圖傳之發射功率與執照規定須查 NCC 規範。 |
| **耗電** | 相機＋VTX 持續發射，AAA 鹼性電池能否支撐須量測。 |
| **缺少既有設計功能** | BLE 手機配網、指令去重、裝置身分註冊等，本方案都沒有。 |

## 4. 安全要求：失聯停車

設計紀錄要求終端失聯時必須自動停車。遙控接收機的 **failsafe（失聯保護）必須設定為「馬達停止」**，不可設為保持最後指令。原型測試時須實際關閉中央發射模組，確認車輛確實停下。

## 5. 階段性發展建議

- **第 0 階段（原型驗證）**：採用本方案（現成模型零件、不寫終端韌體），快速驗證「中央主機看著即時畫面操控便當車」的概念是否可行（對應設計紀錄第 12 節）。
- **後續量產轉型**：原型驗證成功後，依車隊規模與場域需求選擇：
  - 回到 **ESP32＋數位 Wi‑Fi 方案**（可加密、可擴充、可遠端派發），或
  - **混合架構**：ESP32 負責控制與配網，AIO 類比鏡頭僅作低延遲影像通道（見 [BOM_AND_COST_MODEL.md](BOM_AND_COST_MODEL.md) 第 2.3 節）。
